nocturne but better 2.4.1 - package verification
checked september 24, 2026 on windows 11, using windows powershell 5.1.

installer
39 checks ran against throwaway copies of the game files. the real game
folder was not used, and its files were unchanged afterwards.
- every package script parses in windows powershell 5.1.
- install previews (-whatif) leave the game folder unchanged for both
  loaders, and so does the uninstall preview.
- a game without melonloader gets the bundled bepinex and the plugin. a
  repeat install changes nothing.
- upgrading from the published 2.1.2, 2.2.0, or 2.4.0 plugin, or from an
  earlier unpublished 2.3.0 test build, installs 2.4.1 and keeps the old dll
  as a backup. upgrading the 2.2.0, 2.4.0, or test-build melonloader mod
  does the same.
- with melonloader 0.7.3 installed and turned on, the mod goes into mods and
  the bepinex copy is disabled. a melonloader-only game gets no bepinex
  files. a repeat install changes nothing.
- after melonloader is removed, running the installer again brings back the
  bepinex plugin and disables the mods copy. only one copy is ever enabled.
- a melonloader that is turned off in userdata\loader.cfg, or whose proxy
  dll is missing, leaves bepinex in charge.
- a stray folder on the unused loader's path doesn't block the other loader.
- uninstall disables every enabled copy for both loaders, keeps the loaders,
  and repeats cleanly. declining its confirmation is reported as incomplete.
- the installer refuses these without changing any file: an unknown dll in
  either mod location, a corrupt payload, melonloader older than 0.7.3, a
  melonloader 0.5 layout, bepinex beside an enabled melonloader, melonloader
  when it isn't installed or won't start, a different steam build, an
  unknown game asset, a conflicting loader binary, and a disabled doorstop
  configuration. an existing compatible doorstop configuration is kept.

the real installer was also run on the test pc, on nocturne 1.0.1 (steam
build 25487568). without a folder argument it found the steam installation
and upgraded the installed 2.4.0 bepinex plugin to this release, keeping the
old dll as a backup.

after the 1.0.1 update, the 2.4.0 dll loaded every part of the mod in the
updated game, and the source built against the updated game's code with no
changes. the battle was also played on the updated game.

the optional fullscreen script moved to the 1.0.1 files. on a copy of them,
a preview changed nothing, enabling produced the pinned patched file and a
verified backup, a second enable changed nothing, restoring gave back the
original byte for byte, and a 1.0.0 file was refused and left alone.

shareable dlls
- both are built from the 2.4.1 source with debug symbols disabled and no
  git commit hash, so they contain no development-machine paths.
- two clean builds of the source folder with -c Release gave the same
  bytes for both dlls.

gameplay coverage
both loaders were tested in-game with qa builds: the same source plus test
hooks. with the game's auto-play on every lane, the firefly battle ran
through the circle and arrow skins in all three scroll modes, receptor
heights from -10 to +30, note sizes from 70% to 150%, and lane spacings from
70% to 150%, with note flares off and on and enemy attack opacity at 0%,
30%, and 60%. going back to the default layout restored all 70 values the
mod touches. the enemy faded during its attacks and came back after, and
flares were hidden only while the setting was off. the timing bar got
made-up hits, because auto-played hits are left off it. on bepinex, a run
without auto-play pressed the lanes through the game's own input check.
the hit sound and the miss sound were recorded from the pc's output at
several volumes and came out at the set levels. options > gameplay showed
the nine rows and reset them, options > audio showed the four sound rows,
and the title screen and the intro's logo card showed the new text. for
2.4.0, a script sent real key presses to the battle's ready screen: tab,
windows, and alt, alone, with another key, and pressed and released inside
one frame, were all ignored, and j started the fight. the note colors
preview was checked in all six palettes with all three skins.
real key presses, five-lane charts, and enemies other than the firefly
have not been tried.
